# Arquitectura de Ejecución: Async Framework

El Async Framework es la arquitectura de referencia y la plantilla de andamiaje (scaffolding) de nuestra Plataforma Interna de Desarrollo (IDP) diseñada específicamente para la construcción acelerada de Workers asíncronos y consumidores de eventos de alto rendimiento en Python. Mientras que el Transactional Framework gobierna y procesa el plano de control y las solicitudes síncronas HTTP, este framework actúa como el motor de ejecución en segundo plano de la organización, encargado de procesar tareas de alta carga computacional, ejecuciones por lotes (batch) y coreografías distribuidas de datos.

Su integración resuelve de manera formal el desacoplamiento temporal de los sistemas, abstrayendo las complejidades de la concurrencia no bloqueante y garantizando que los servicios pesados escalen de forma predecible sin degradar la experiencia de usuario en las interfaces web.

## Capacidades de Infraestructura y Resiliencia Cohesiva:
Concurrencia Nativa no Bloqueante (asyncio): El núcleo del framework está estructurado en torno al ciclo de eventos (event loop) de Python, optimizando la gestión de E/S de red masiva (peticiones a bases de datos, webhooks, llamadas a microservicios). Esto permite que cada Worker mantenga una huella de memoria extremadamente baja mientras procesa de forma concurrente cientos de eventos por segundo, elevando la eficiencia de costos en la nube.

Trazabilidad Distribuida Context-Aware: Fiel a nuestro principio de gobernanza y observabilidad, el framework integra un middleware interceptor que extrae el Correlation ID incrustado nativamente en los metadatos o cabeceras de los mensajes entrantes del clúster. Al sincronizar este identificador con el componente logger-tracker antes de invocar la lógica de negocio, se asegura que la ejecución en segundo plano comparta la misma línea de telemetría y auditoría que originó la transacción en las APIs transaccionales.

## Robustez y Tolerancia a Fallos en Producción
El procesar eventos de forma desacoplada elimina el contexto del cliente web, lo que exige que el software cuente con mecanismos autónomos de autosanación y contención de errores:

Estrategia Automática de Reintentos y DLQ (Dead Letter Queues): El framework se integra de forma directa con nuestro global-handler especializado. Ante errores transitorios (como timeouts de bases de datos o servicios de terceros), el sistema implementa políticas de reintento exponencial con aleatoriedad (Exponential Backoff with Jitter). Si el error persiste y se clasifica como no recuperable, el framework intercepta la excepción e impide el bloqueo de la cola de mensajería (Poison Pill), redirigiendo el mensaje malformado hacia una cola de descarte (DLQ) para su posterior auditoría y depuración por el equipo de SRE.

Ciclo de Vida Controlado (Graceful Shutdown): Los Workers están diseñados para ser totalmente sensibles a señales del sistema operativo e infraestructura de orquestación (como SIGTERM o SIGINT). Ante un despliegue continuo o un evento de escalado hacia abajo (scale-down), el framework detiene la ingesta de nuevos mensajes, completa de manera segura el procesamiento del evento en curso, vacía los buffers y cierra limpiamente las conexiones de persistencia antes de liberar el contenedor, garantizando la consistencia transaccional absoluta de los datos.
